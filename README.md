# Parkly

**Меньше кругов по городу — больше времени на жизнь.**

Parkly — мобильное приложение (PWA и Android) для поиска парковки. Оно отвечает на вопрос
«Где мне лучше припарковаться к моменту приезда?». В Алматы работает демо с прогнозом свободных мест,
ценой и бронью. По всему Казахстану есть каталог реальных парковок из OpenStreetMap, а помощнику Пину
можно написать своими словами.

Проект для защиты по теме Smart City. Для запуска не нужны ни API-ключи, ни регистрация в сторонних сервисах.

**Онлайн:** https://systemdfan-0.github.io/parkly/ · **APK:** [Releases](https://github.com/systemdfan-0/parkly/releases/latest).
Сайт и обновления работают с GitHub — ноутбук для этого включать не нужно (см. «Сервер без ноутбука»).

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev          # http://localhost:5180 и адрес в локальной сети для телефона
```

Production-сборка (с service worker и офлайн-кэшем):

```bash
npm run build
npm run preview      # http://localhost:4173 и адрес в локальной сети
npm test             # тесты: брони, прогноз, ML, Пин (подбор и разговор), каталог, привязка демо к OSM, обновления
```

Как открыть на телефоне:

- **В той же Wi-Fi сети.** Откройте адрес `http://192.168.x.x:4173`, который печатает `npm run preview`.
  Приложение работает, но установить его как PWA по http не получится.
- **По ссылке с установкой.** Загрузите папку `dist/` на любой статический HTTPS-хостинг
  (Netlify Drop, GitHub Pages, Vercel). Пути в сборке относительные, работает и из подпапки.
  После этого в Chrome появится пункт «Установить приложение».

### Android (APK)

Android-версия — та же сборка, упакованная через Capacitor 6 в папку `android/`. Веб-файлы
лежат внутри APK, поэтому интернет нужен только для карты и поиска адреса. Кнопка «Назад»
закрывает окно, затем карточку, затем возвращает на карту и в конце выходит из приложения.

Нужны JDK 17 и Android SDK 34 (путь к SDK записан в `android/local.properties`).

```bash
npm run build && npx cap sync android
```

```bash
cd android && ./gradlew assembleDebug
```

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`. Его можно скинуть на телефон
и установить, разрешив установку из неизвестных источников. Он подписан отладочным ключом:
для показа этого достаточно, для Google Play нужна release-сборка со своим ключом. Открыть проект
в Android Studio: `npx cap open android`.

Подложка карты — векторная карта [OpenFreeMap](https://openfreemap.org) (данные OpenStreetMap, без ключа
и лимитов) на MapLibre: чёткая на любом экране, подписи по-русски. Если WebGL недоступен или стиль не
загрузился, включаются обычные растровые тайлы OpenStreetMap. Просмотренные куски карты кэшируются:
если перед защитой один раз пройти сценарий с интернетом, он заработает и без сети. Если карта не
загрузилась совсем, Parkly рисует схему главных улиц, а парковки и прогноз продолжают работать.

## Сценарий защиты (около минуты)

Демо стартует в сценарии «Будни, 18:25», это вечерний пик. Часы в правом верхнем углу открывают демо-панель.

1. **Поиск.** Введите «Достык Плаза» (подойдут и «dostyk», и «дп»). Карта приблизится к ТРЦ, внизу появятся 5 вариантов.
2. **Разница между вариантами.** В результатах есть четыре метки:
   - **Ближе ко входу**: подземный паркинг ТРЦ. До входа 1 минута, но сейчас осталось 2 места. Модель даёт к приезду широкий диапазон 0–17 и шанс около 70%: большой паркинг ТРЦ то пустеет после сеансов, то снова заполняется.
   - **Дешевле**: улица Жолдасбекова, 225 ₸ за 2 часа (после 20:00 стоянка бесплатная), без брони.
   - **Надёжнее**: гостевые места ЖК, шанс 100%, но идти 11 минут.
   - **Лучший выбор**: парковка бизнес-центра. Сейчас 4 места, а к 18:36 ожидается 7–10 (ML-модель): сотрудники разъезжаются после 18:00.
3. **Детали.** Нажмите на карточку или на метку. Откроется маршрут «выезд → парковка → у входа» по времени,
   график свободных мест на час, цена с разбивкой и выбор длительности. От парковки до входа на карте
   нарисована жёлтая пунктирная линия, похожая на дорожную разметку.
4. **Бронирование.** «Забронировать за 600 ₸», затем «Подтвердить демо-бронь». Появится код брони, на метке
   станет на одно место меньше, на вкладке «Брони» появится бейдж.
5. **История и расходы.** На вкладке «Брони» видны активная бронь, расходы за месяц и прошлые поездки.
6. **Отмена.** «Отменить бесплатно» возвращает место на парковку, бронь уходит в историю как отменённая.
7. **Перезагрузка.** После обновления страницы назначение, брони, избранное и демо-время сохраняются.

Дополнительные сюжеты для вопросов:

- **Проверка прогноза.** Выберите парковку → часы → «Перемотать до приезда и сравнить». Время сдвинется
  на время в пути, и появится сообщение «ждали 8–12, по факту 10».
- **Уведомление о месте.** Выберите «Подземный паркинг Dostyk Plaza» → часы → «1. Занять все места» →
  «2. Следить» → «3. Три машины уехали». Придёт уведомление «Освободилось место» с кнопкой брони.
- **Другое время суток.** В демо-панели можно выбрать утро, обед, ночь или субботу. Ночью уличные зоны
  бесплатны, а рынок и парковка КБТУ закрыты. В субботу заняты ТРЦ, парки и Медеу.
- **Недоступность.** На «Зелёном базаре» парковка рынка недоступна: она закрывается в 19:00, и после
  приезда останется меньше 30 минут. У Esentai Mall парковка P2 временно закрыта.
- **Пустой поиск.** Запрос «Хогвартс» покажет «Ничего не нашли» и кнопку поиска адреса в OpenStreetMap.
  Если удерживать палец на карте вдали от городов, Parkly покажет «В каталоге OSM нет парковок в 3 км».
- **Другие города.** Напишите Пину «У Хан Шатыра, до 500 тенге в час» или выберите город на главном экране.
  Парковки там из OpenStreetMap: цена, доступ и вместимость — как в OSM, занятость — «Нет данных».

Направления с разными результатами: Dostyk Plaza (у каждого варианта свой компромисс), MEGA (бесплатно
и много мест, выигрывает ближайший вход), театр Абая (перед спектаклем в 19:00 площадка у театра
заполняется), Зелёный базар (рынок закрывается), вокзал Алматы-2 (короткая стоянка до часа),
Медеу (нижняя парковка с трансфером).

## Как работает прогноз

До 15 минут до приезда прогноз даёт **офлайн ML-модель** (дерево решений). Если ехать дольше
или нет свежих замеров, работает **эвристика потоков**. Карточка, график и Пин подписывают источник:
«ML-модель» или «эвристика».

### Офлайн ML-модель

Обучение воспроизводимо и идёт на CPU примерно за 5 секунд:

```bash
npm run ml:setup
```

```bash
npm run ml
```

`npm run ml` выполняет три шага:

1. `ml:meta` — выгружает парковки и профили из кода приложения в `ml/meta.json`.
2. `ml:train` (`ml/train.py`, scikit-learn) — генерирует историю, обучает три дерева (на +5, +10 и +15 мин)
   и экспортирует их в `src/ml/model.json`.
3. `ml:compare` — запускает дерево из TypeScript тем же кодом, что в APK, сравнивает его с эвристикой
   приложения на тех же тестовых днях и пишет [ml/REPORT.md](ml/REPORT.md).

- **Данные синтетические**: реальных замеров с датчиков нет. 4 недели поминутной истории
  37 демо-парковок. У каждой парковки свой сдвиг пика. Есть дождливые дни, пятничный вечер,
  киносеансы, события на стадионе, перекрытия въезда и ошибка датчика ±1. Эвристика этих особенностей не знает.
- **Признаки** (только то, что известно к моменту прогноза): время суток, день недели, выходной,
  тип и вместимость парковки, свободные места сейчас и 5/10/15 минут назад.
- **Цель**: свободные места через 5/10/15 минут. Для 11 минут прогноз интерполируется между деревьями на +10 и +15.
- **Разбиение по целым дням**: обучение на днях 1–21, проверка на днях 22–28.
- **Модель**: `DecisionTreeRegressor(max_depth=8, min_samples_leaf=300)`. Точка прогноза — среднее листа,
  диапазон — 20–80% квантили листа, шанс — доля примеров листа, где осталось хотя бы одно место.

Фактические результаты на тестовых днях (средняя абсолютная ошибка, мест):

| Горизонт | Дерево | Эвристика приложения | «Останется как сейчас» |
|---|---|---|---|
| +5 мин | **2,30** | 2,65 | 2,62 |
| +10 мин | **3,26** | 3,81 | 4,01 |
| +15 мин | **3,75** | 4,72 | 5,25 |

TypeScript и Python дают одинаковый точечный прогноз в 70 665 из 70 665 тестовых случаев.
Модель — JSON на 55 КБ внутри APK, без сети, API-ключа и сервера.

### Эвристика (дальше 15 минут)

Эвристика — модель потоков без машинного обучения.

**Данные для каждой парковки:**

| Данные | Откуда в реальной системе | В демо |
|---|---|---|
| Свободные места сейчас | датчики или камеры на въезде | симуляция |
| Суточный профиль загрузки (по часам, будни и выходные) | средние по истории за 4–8 недель | эвристика по типу объекта: ТРЦ, офис, рынок, улица, театр, вокзал, жилой дом, парк, вуз, стадион |
| Средняя длительность стоянки (оборот) | история въездов и выездов | ТРЦ 2 ч, офис 5 ч, рынок 1 ч, вокзал 45 мин… |
| Ёмкость, часы работы, тариф | оператор парковки | демо-данные |
| Брони Parkly | собственная база | реальные (localStorage) |
| Время в пути | навигационный сервис | расстояние × 1,35 / средняя скорость в этот час (в вечерний пик около 16 км/ч) |

**Расчёт** (`src/engine/model.ts`):

1. Каждую минуту до приезда уезжает `занято ÷ средняя_стоянка` машин. Приезжает столько же плюс
   изменение суточного профиля за эту минуту. Если сейчас загрузка отличается от профиля, разница
   сглаживается примерно за 25 минут.
2. Въезд и выезд случайны (Пуассон), поэтому модель прогоняется 240 раз. Въехать на заполненную
   парковку нельзя: такие водители ищут место дальше.
3. Диапазон «4–6» — это 20-й и 80-й процентили этих прогонов. Шанс — доля прогонов, в которых к приезду
   есть хотя бы одно место.

Поэтому поведение меняется со временем суток. Вечером парковки офисов освобождаются, ТРЦ заполняются.
Перед спектаклем заполняется площадка у театра. Перед закрытием рынка его парковка пустеет. Ночью улицы
бесплатны, а часть парковок закрыта.

**Подбор** (`src/engine/recommend.ts`). Каждому варианту начисляется оценка в минутах:
путь + пешком до входа + (1 − шанс) × 15 мин (круг по району и переезд на запасную парковку)
+ 5 мин на поиск места вдоль улицы, если брони нет, + цена ÷ 50 ₸/мин. Переключатель
«Ближе / Дешевле / Надёжнее» меняет веса. Метки «Ближе ко входу», «Дешевле» и «Надёжнее» ставятся
по одному признаку. Текст объяснения собирается из тех же чисел, что видны в карточке.

**Честная оговорка.** В демо симулятор и прогноз используют одну и ту же модель, поэтому прогноз
калиброван по построению. Тест проверяет, что факт попадает в 60%-й диапазон примерно в 60% случаев.
В реальном городе параметры профилей и оборота нужно калибровать по истории датчиков.

## Пин — помощник

Поле «Спросить Пина» лежит на карте над панелью. Пишите своими словами:

- «У Хан Шатыра, до 500 тенге в час»
- «Куда лучше встать у Достык Плазы через 15 минут?»
- «вокзал в Караганде», «Хан Шатыр жанында тұрақ қайда?»

Пин понимает:
- город, включая казахские и старые названия: Қарағанды, Өскемен, Нур-Султан, Чимкент, Алма-Ата;
- место назначения в падеже («у Хан Шатыра», «Достык Плазы»), на латинице («Khan Shatyr») и по категории («вокзал»);
- бюджет («до 500 тенге в час», «бесплатно»), время приезда («через 15 минут», «10 минуттан кейін»), длительность («на 3 часа») и приоритет («поближе», «надёжнее»);
- короткие уточнения к прошлому запросу: «а поближе?», «тогда до 700», «а через 15?»;
- вопросы про парковку из прошлого ответа: «а сколько стоит?», «сколько там мест?», «она круглосуточная?»,
  «можно забронировать?», «далеко идти?»;
- «рядом со мной» — подбор у текущей геопозиции;
- вопросы про приложение и данные: «что ты умеешь?», «откуда данные?», «как работает прогноз?»,
  «сколько парковок в Шымкенте?», «как отменить бронь?», «что значат цвета меток?»;
- разговор: «привет», «спасибо», «рахмет», «пока». На вопросы не по теме (погода, курс доллара)
  и про то, чего нет в данных (штрафы, эвакуация), Пин прямо говорит, что не знает, и не выдумывает.

Ответ — не больше двух предложений и кнопка «Показать на карте». Она открывает парковку на карте
с теми же условиями. Если подходящего нет, Пин предлагает изменить одно условие кнопкой:
«Поднять до N ₸», «Без ограничения по цене», «Искать в: Аягоз». Если место неоднозначно,
Пин задаёт один вопрос («Уточните город: Алматы, Туркестан, Астана или Шымкент?»)
и даёт варианты кнопками.

Как устроено: правила и словари на телефоне, без сети и без платных API
(`src/engine/pinText.ts` — разбор фразы, `src/engine/pinTalk.ts` — вопросы и разговор, `src/catalog/geo.ts` и `src/catalog/text.ts` — поиск мест
с падежами, казахскими буквами и транслитом). Факты в ответе берутся только из расчётов
(`src/engine/pinReply.ts`):
- в Алматы — из демо-подбора с ML-прогнозом и пометкой «демо-данные, ML-модель»;
- в остальных городах — из каталога OSM. Там нет занятости, поэтому Пин так и говорит: «занятость — нет данных».

Сценарий защиты — ссылка в окне Пина. Она ставит будни 18:25 и отправляет «У театра Абая через 5 минут»,
затем «а через 15?». Совет меняется с парковки у театра на Панфилова, и Пин объясняет причину.

## Каталог парковок Казахстана (OpenStreetMap)

Импорт повторяемый:

```bash
npm run catalog:setup
```

```bash
npm run catalog
```

Скрипт `catalog/import.py`:
1. Скачивает выгрузку Geofabrik «Kazakhstan» (`kazakhstan-latest.osm.pbf`, 215 МБ) и сверяет MD5.
2. Берёт дату данных из заголовка PBF.
3. Извлекает `amenity=parking` (точки и полигоны), населённые пункты, области и 13 154 ориентира для поиска.
4. Пишет `public/catalog/` (2,2 МБ, внутри APK) и отчёт [catalog/COVERAGE.md](catalog/COVERAGE.md).

Разбор занимает около 50 секунд. Для новой выгрузки: `npm run catalog -- --refresh`.

Текущая выгрузка — данные OSM на **17.11.2026 21:24 UTC**:
- **11 486 парковок** в 481 населённом пункте и 20 регионах;
- больше всего в Алматы (2 342), Астане (1 429), Актобе (913), Атырау (653), Усть-Каменогорске (635);
- в Шымкенте — 164.

Что известно из OSM:
- платность — у 12% парковок, из них бесплатных 9%;
- вместимость — у 5%;
- доступ — у 14%, из них частных 231;
- название — у 1%;
- занятость — ни у одной.

Всё неизвестное приложение показывает как «Нет данных». Частные парковки участвуют в подборе,
но стоят ниже, помечены «Частная» и упоминаются в ответе Пина. Гаражные кооперативы (7) исключены.
Покрытие по областям и городам — на главном экране: «Каталог: 11 486 парковок».

Парковки разбиты на квадраты 0,25°. Загружаются только квадраты текущего района карты.
При отдалении точки группируются в кластеры с числом, при сильном отдалении — по квадратам каталога
без загрузки самих точек. На эмуляторе вид на всю страну — 21 метка, без длинных задач.

Демо-данные помечены явно:
- «Демо» на карточках Алматы;
- «демо-бронь» в подтверждении;
- «демо-данные, ML-модель» в ответах Пина;
- метка «Старт (демо)» на карте.

## Сервер без ноутбука (GitHub Pages + Releases)

Своего сервера у Parkly нет и не нужно: всё считается на телефоне, а раздачу берёт на себя GitHub.

- **Сайт** — https://systemdfan-0.github.io/parkly/. Каждый пуш в `main` запускает
  [.github/workflows/pages.yml](.github/workflows/pages.yml): тесты → сборка → выкладка на GitHub Pages.
  Сайт ставится на телефон как PWA (Chrome → «Установить приложение») и работает офлайн.
- **APK** — в [Releases](https://github.com/systemdfan-0/parkly/releases). Ссылку можно просто отправить другу.
- **Обновления** — приложение раз в 12 часов и при запуске читает
  `https://systemdfan-0.github.io/parkly/manifest.json`; там версия, список изменений, ссылка на APK и sha256.

Выпустить новую версию (нужны `gh` с входом в GitHub, JDK 17 и Android SDK):

1. Поднять `versionCode` и `versionName` в [release.config.json](release.config.json).
2. Описать изменения пунктами «- …» в [RELEASE_NOTES.md](RELEASE_NOTES.md).
3. Запустить:

```bash
npm run release
```

Скрипт [scripts/publish-release.sh](scripts/publish-release.sh) прогоняет тесты, собирает APK, создаёт релиз
`vX.Y` с файлом, пишет `public/manifest.json` и пушит — через 1–2 минуты телефоны увидят обновление.
APK подписан отладочным ключом этого компьютера: обновление встанет поверх версии, собранной здесь же.

## Обновления Android-приложения

- **Где задать адрес**: [release.config.json](release.config.json) → `manifestUrl` (HTTPS). Там же
  `versionCode`/`versionName` для сборки и `trustedHosts` — хосты, с которых можно скачивать APK.
  Пока адрес пустой, приложение пишет «Адрес релизов не настроен».
- **Манифест**:
  ```json
  { "versionCode": 2, "versionName": "1.1", "changes": ["…"],
    "apkUrl": "https://github.com/…/Parkly-1.1.apk", "sha256": "…", "size": 5325961, "publishedAt": "2026-11-19" }
  ```
- **Когда проверяется**: при запуске, по кнопке «Проверить обновления» (Избранное → Приложение)
  и в фоне через WorkManager (раз в 12 часов, только при наличии сети). Все три пути используют
  один Java-код (`android/app/src/main/java/kz/parkly/demo/updates/`).
- **Уведомление** показывается один раз для каждого versionCode. По нажатию открывается экран
  «Что нового» с кнопкой «Скачать APK». После скачивания сверяется sha256, затем открывается
  стандартное окно Android «Обновить приложение?».
- **Если уведомления выключены**, обновление показывается баннером внутри приложения при следующем запуске.
- **Безопасность**: только HTTPS и доверенные хосты. Тестовый сервер `http://10.0.2.2:8787`
  принимает только отладочная сборка.

Проверка без хостинга релизов:

```bash
npm run release:test
```

```bash
npm run release:test-server
```

Первая команда собирает тестовую версию 1.1 (versionCode 2) и манифесты в `release-test/`,
вторая отдаёт их эмулятору. В демо-панели (часы) выберите канал «Тест: новая версия».

  и выбор Parkly с ML-прогнозом. **Это симуляция**, не замеры. Итог: 3,0% → 2,0% приездов на полную
  ценой +1 мин пешком; когда у ближайшей сейчас 0–3 места — 29,9% → 15,5%. Утром разницы нет

  привязка к парковке снимается.

  ```bash
  npm run pilot:import -- data/pilot/test-measurements.csv --source "Тестовый набор"
  ```

  Проверяет пропуски, дубликаты и конфликты, невозможные значения (свободных больше вместимости,
  отрицательные, нецелые), время в будущем и разрывы между замерами длиннее 30 минут; печатает отчёт и

  за 20 минут. Один и тот же поток водителей (время в пути, лимиты цены и ходьбы, 10% отмен)
  прогоняется в двух режимах: «каждому отдельно» и «с учётом выбравших» (тот же ML-прогноз, но из мест
  вычитаются машины, которые уже выбрали парковку и приедут раньше; отмена возвращает место).
  На экране — загрузка каждой парковки, доля приездов на полную, средняя ходьба и ответ Пина с числами.
  Тот же номер потока даёт тот же результат.

  | Машин | На полную: отдельно → с учётом | Пешком, мин | Не встали рядом |
  |---|---|---|---|
  | 20 | 61% → 33% | 5,8 → 6,3 | 0 → 0 |
  | 40 | 67% → 31% | 6,3 → 6,4 | 0 → 0 |
  | 80 | 79% → 35% | 7,0 → 7,1 | 0 → 1 |
  | 120 | 84% → 43% | 7,9 → 8,2 | 7 → 7 |
  | 160 | 90% → 55% | 8,3 → 8,6 | 26 → 23 |
  | 200 | 90% → 67% | 9,1 → 9,2 | 40 → 40 |

  Учёт выбравших всегда стоит немного ходьбы. При перегрузке (200 машин) мест не хватает обоим режимам.
  У самой ближней парковки «У театра» он даже хуже: при 80 машинах туда едут 18 машин вместо 9 и 15
  из них приезжают на полную — прогноз фонового потока там занижен. Проверки: `tests/event.test.ts`
  (детерминизм, один поток для обоих режимов, отмена освобождает ожидаемое место).

  [src/data/anchors.json](src/data/anchors.json). Раньше точки ставились «на глаз» и промахивались на 100–700 м.
- Ёмкость, тарифы, часы работы и загрузка демо-парковок — демонстрационные данные.
- Оплата не списывается. Брони, отмена, избранное, уведомления и история работают по-настоящему
  и хранятся в браузере.
- Три прошлые поездки в истории отмечены как «(демо)», чтобы раздел расходов не был пустым.
- Точный адрес ищется в OpenStreetMap (Nominatim) только по нажатию кнопки, без ключа.

## Устройство проекта

```
catalog/import.py       импорт парковок OSM (Geofabrik) → public/catalog/, отчёт catalog/COVERAGE.md
src/catalog/            загрузка квадратов каталога, поиск городов и мест, подбор без данных о занятости
src/engine/pinText.ts   понимание свободного текста для Пина (локальные правила)
src/engine/pinReply.ts  ответ Пина: ≤ 2 предложений из подбора, каталога и ML
art/, scripts/make-icons.sh   иконка Parkly и её сборка для Android и PWA
ml/train.py             генератор синтетической истории + обучение дерева (Python, CPU)
ml/compare.task.ts      сравнение дерева и эвристики на тестовых днях → ml/REPORT.md
ml/arrivals.task.ts     доля приездов на полную: «ближайшая с местами» vs Parkly → ml/REPORT.md
scripts/import-measurements.ts   импорт замеров пилота из CSV → public/pilot/measurements.json
data/pilot/             тестовый набор замеров (помечен как тестовый)
release.config.json     версия приложения, адрес манифеста релизов, доверенные хосты
scripts/                тестовый релиз 1.1 и тестовый сервер манифестов
src/
  ml/                   признаки, запуск дерева (model.json) в браузере и APK
  engine/pin.ts         реплики Пина из данных подбора и прогноза
  updates/              проверка манифеста, канал, баннер; мост к Android-плагину
  data/places.ts        ориентиры, улицы, парковки (демо-данные)
  engine/profiles.ts    суточные профили, оборот, объяснения трендов
  engine/model.ts       симуляция въезда/выезда, прогноз Монте-Карло, часы работы, брони
  engine/recommend.ts   подбор, метки, объяснения
  engine/event.ts       симуляция «После мероприятия»: два режима на одном потоке
  car/, nav.ts          «Где моя машина», ссылки «Ко въезду» / «К парковке»
  pilot/                разбор и проверка CSV с замерами пилота
  engine/pricing.ts     тарифы: бесплатные минуты, платные часы, суточный максимум
  engine/search.ts      поиск: ориентиры, транслит, казахские буквы, улицы, OSM
  engine/scenarios.ts   демо-сценарии времени, начальное состояние
  store.ts              состояние (zustand + localStorage), уведомления
  components/           карта (Leaflet), шторка, карточки, детали, брони, демо-панель
tests/engine.test.ts    тесты согласованности
```
